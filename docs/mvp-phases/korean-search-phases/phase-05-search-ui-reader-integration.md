# Phase 05: 검색 UI와 리더 연결

## 목표

사용자가 한글 키워드를 입력하고 검색 결과를 확인한 뒤, 선택한 구절의 리더 위치로 이동할 수 있게 한다. 모바일에서도 검색 입력, 필터, 결과 목록, 리더 이동 흐름이 깨지지 않아야 한다.

## 선행 조건

- Phase 04의 한국어 검색 API가 동작한다.
- 기존 리더가 `bookId`, `chapter`, `verseKey` 또는 동등한 식별자로 위치 이동할 수 있다.
- 기존 앱 상태 관리 방식과 URL 상태 유지 정책을 확인했다.

## 산출물

- 한국어 검색 입력 UI
- 언어/정렬/권 필터 UI
- 검색 결과 목록
- 결과 없음/로딩/오류/짧은 검색어 상태
- 검색 결과에서 리더 이동 처리
- 모바일 레이아웃 검증 결과

## UX 정책

- 검색어 입력 후 debounce를 적용하거나 명시적 검색 버튼을 둔다.
- 기본 언어는 `ko`로 둔다.
- 기본 정렬은 `canonical`로 둔다.
- 결과 항목에는 성경 위치와 한국어 본문을 우선 표시한다.
- 영어 KJV 원문은 보조 텍스트 또는 펼침 영역으로 제공한다.
- 결과 선택 시 해당 장을 열고 해당 절을 화면에 드러낸다.

## 구현 체크리스트

- [x] 검색 입력 컴포넌트 위치를 정한다.
- [x] 검색어 상태와 URL query 동기화 여부를 결정한다.
- [x] `lang=ko` 기본값을 적용한다.
- [x] 검색 요청 debounce 또는 submit 방식을 구현한다.
- [x] 검색 중 loading 상태를 표시한다.
- [x] 검색어가 너무 짧은 상태를 표시한다.
- [x] 결과 없음 상태를 표시한다.
- [x] API 오류 상태를 표시한다.
- [x] 결과 항목에 `책 이름`, `장:절`, `textKo`를 표시한다.
- [x] 결과 항목에 필요한 경우 `textEn`을 함께 표시한다.
- [x] 결과 항목 클릭 또는 버튼으로 리더 이동을 연결한다.
- [x] 권 필터를 검색 API의 `bookId` 파라미터와 연결한다.
- [x] 구약/신약 필터를 검색 API의 `testament` 파라미터와 연결한다.
- [x] 정렬 선택을 `sort` 파라미터와 연결한다.
- [x] 검색 결과 수가 많을 때 추가 로딩 또는 페이지네이션 정책을 정한다.

## 모바일 체크리스트

- [x] 360px 폭에서 검색 입력 텍스트가 잘리지 않는다.
- [x] 필터 컨트롤이 한 줄에 과도하게 압축되지 않는다.
- [x] 결과 항목의 터치 영역이 충분하다.
- [x] 검색 결과 목록이 하단 네비게이션 또는 고정 플레이어에 가리지 않는다.
- [x] 장문 한국어 구절이 카드/목록 영역 밖으로 넘치지 않는다.
- [x] 리더 이동 후 해당 절이 화면에서 확인 가능하다.

## 접근성 체크리스트

- [x] 검색 입력에 접근 가능한 label이 있다.
- [x] 자동 검색 방식이라 별도 검색 버튼은 두지 않고, 입력/필터/결과 이동 버튼에 접근 가능한 이름이 있다.
- [x] 필터 select/control에 label이 있다.
- [x] 로딩 상태가 스크린리더에 과도하게 반복 공지되지 않는다.
- [x] 결과 항목은 키보드로 이동 및 선택 가능하다.
- [x] 검색 결과 선택 후 focus 이동 정책을 정한다.

## 검증 체크리스트

- [x] `믿음` 입력 시 한국어 결과가 표시된다.
- [x] 결과 항목을 선택하면 해당 장/절로 이동한다.
- [x] `예수 그리스도` 검색 시 결과 목록이 표시된다.
- [x] 권 필터 변경 시 결과가 갱신된다.
- [x] 정렬 변경 시 결과 순서가 갱신된다.
- [x] 검색어 삭제 시 빈 상태가 표시된다.
- [x] API 실패 시 사용자가 재시도할 수 있다.

## 완료 기준

- 사용자가 한글 키워드로 구절을 찾고 리더로 이동하는 핵심 흐름을 완료할 수 있다.
- 모바일과 데스크톱에서 검색 UI가 겹치거나 잘리지 않는다.
- 검색 UI가 기존 리더, 강조, 인용 기능을 방해하지 않는다.
