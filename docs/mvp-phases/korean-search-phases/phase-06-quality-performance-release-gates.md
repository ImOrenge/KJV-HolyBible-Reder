# Phase 06: 품질, 성능, 출시 게이트

## 목표

한글 검색 기능을 공개 환경에 올리기 전에 성능, 보안, 데이터 무결성, 회귀 위험을 검증한다. 이 단계는 구현 완료 여부를 판단하는 최종 게이트다.

## 선행 조건

- Phase 01-05가 완료되어 있다.
- staging DB에 실제 한국어 승인 본문이 import되어 있다.
- 검색 API와 UI가 staging 환경에서 접근 가능하다.

## 산출물

- 검색 성능 측정 결과
- 대표 검색어 smoke test 결과
- 보안/RLS 검증 결과
- 모바일/접근성 확인 결과
- release readiness 체크리스트

## 성능 체크리스트

- [x] 대표 검색어별 DB 함수 `explain analyze` 결과를 기록한다.
- [x] 단일 키워드 검색 p95가 300ms 이하인지 확인한다.
- [x] phrase 검색 p95가 600ms 이하인지 확인한다.
- [x] API 전체 응답 p95가 1초 이하인지 확인한다.
- [x] `limit=50` 기본 응답 payload 크기를 확인한다.
- [x] `limit=100` 최대 응답 payload 크기를 확인한다.
- [x] `bookId` 필터 적용 쿼리가 인덱스를 사용하는지 확인한다.
- [x] `testament` 필터 적용 쿼리가 과도한 full scan을 만들지 않는지 확인한다.
- [x] 검색 결과 렌더링이 모바일에서 지연되지 않는지 확인한다.

## 보안 체크리스트

- [x] 비공개 한국어 번역이 API 결과에 포함되지 않는다.
- [x] 미승인 한국어 번역이 API 결과에 포함되지 않는다.
- [x] 검색 API가 service role key에 의존하지 않는다.
- [x] 공개 본문 검색 외 사용자 데이터는 노출되지 않는다.
- [x] 함수 권한이 필요한 role에만 부여되어 있다.
- [x] 신규 테이블을 exposed schema에 만들었다면 RLS와 grant 정책을 검토했다.
- [x] 오류 응답이 내부 SQL, secret, 환경 변수를 노출하지 않는다.

## 데이터 무결성 체크리스트

- [x] `bible_verses_ko` 공개 승인 행 수와 검색 컬럼 채움 행 수가 일치한다.
- [x] `verse_key`가 `bible_verses_en`에 존재하지 않는 한국어 공개 행이 없다.
- [x] 검색 결과의 `book_order`, `chapter`, `verse`가 원문과 일치한다.
- [x] 같은 `verse_key`가 한 검색 응답에서 중복 반환되지 않는다.
- [x] 번역본이 여러 개 있을 때 기본 공개 번역본만 반환된다.

## UI 회귀 체크리스트

- [x] 기존 영어 검색 또는 fixture 검색 흐름이 의도대로 유지된다.
- [x] 리더의 권/장 선택이 검색 기능 추가 후 깨지지 않는다.
- [x] 강조, 인용 저장, 복사 기능이 검색 결과 이동 후에도 동작한다.
- [x] 모바일 하단 네비게이션과 검색 결과 목록이 겹치지 않는다.
- [x] 검색 결과에서 리더 이동 후 브라우저 뒤로 가기 동작이 자연스럽다.

## 출시 게이트

- [x] staging에서 대표 검색어 10개가 모두 200 응답을 반환한다.
- [x] 대표 검색어 10개 중 결과가 0인 항목은 의도된 이유가 문서화되어 있다.
- [x] p95 API 응답 1초 이하 목표를 만족한다.
- [x] 비공개/미승인 번역 노출 테스트가 통과한다.
- [x] 모바일 폭 직접 검증이 완료되어 있다.
- [x] release note에 한글 검색 범위와 한계를 기록한다.
- [x] rollback 기준과 비활성화 방법이 정리되어 있다.

## 완료 기준

- 한글 검색 기능이 staging에서 안정적으로 검증되었다.
- 성능, 보안, 데이터 무결성, UI 회귀 체크리스트가 통과했다.
- 공개 배포 전 남은 위험과 후속 개선 항목이 문서화되어 있다.
